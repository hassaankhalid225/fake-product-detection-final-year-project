CHAPTER 1: INTRODUCTION
================================================================================

The proliferation of counterfeit goods has become one of the most challenging issues facing modern commerce, public health systems, and consumer safety. Across pharmaceuticals, luxury goods, electronics, and food products, fake items cause measurable harm both economically and physically. This chapter introduces the problem domain, defines the objectives of the proposed system, enumerates the technologies employed, and outlines the overall scope and contributions of the research.

1.1 PROBLEM STATEMENT
The proliferation of counterfeit products has become a significant global issue, affecting various industries ranging from pharmaceuticals to luxury goods. Traditional anti-counterfeiting methods, such as holographic stickers, RFID tags, and centralized databases, are often prone to tampering, duplication, or lack of consumer access. These methods rely on a single point of control — a central authority — whose database, if compromised, renders the entire verification system untrustworthy.

Consumers currently have no reliable way to verify the complete journey of a product from the manufacturer to the retail shelf. This lack of transparency leads to substantial economic losses for legitimate manufacturers and poses severe health and safety risks to consumers. For instance, counterfeit medications can be lethal, while fake electronics can cause fire hazards. The World Health Organization estimates that up to 10% of medicines globally are counterfeit, disproportionately affecting developing nations.

This study proposes a blockchain-based solution that decentralizes the trust model entirely. By recording every stage of a product's lifecycle on an immutable distributed ledger, the system eliminates single points of failure and gives consumers transparent, tamper-proof access to product provenance data.

1.2 OBJECTIVES
The primary objectives of this project are defined as follows:
1. To develop a decentralized platform for product verification that ensures data integrity and prevents unauthorized tampering of records.
2. To implement a transparent supply chain tracking mechanism where every transfer of ownership is permanently recorded on a public or consortium ledger.
3. To provide a user-friendly interface for consumers to verify product authenticity using simple QR code scans without requiring specialized hardware.
4. To demonstrate the practical feasibility of deploying smart contracts for automated enforcement of supply chain rules.
5. To create a hybrid architecture that combines the speed of off-chain databases with the security guarantees of on-chain immutability.

1.3 TECHNOLOGIES USED
The system is built using a carefully selected technology stack:
- Blockchain Engine: Ethereum (utilizing Hardhat for local development).
- Smart Contracts: Solidity.
- Backend Framework: Node.js with Express.js.
- Database: MongoDB for metadata caching.
- Frontend: React.js with Vite.
- Web3 Integration: Ethers.js.
- QR Code Library: qrcode.react and html5-qrcode.

1.4 TECHNIQUES
The system employs:
- Smart Contract Enforcement: Automated rules on product transfers.
- Deterministic Hashing: Generating unique reproducible identifiers.
- QR Code Bridging: Linking physical products to their digital ledger twins.
- Hybrid Data Architecture: Balancing on-chain security with off-chain performance.
- Event-Driven Logging: Real-time audit trails via Ethereum events.

1.5 SCOPE
The scope encompasses the product lifecycle involving:
- Manufacturers: Initial product registration.
- Distributors: Intermediate ownership updates.
- Retailers: Final sale marking.
- Consumers: Public verification scanning.

1.6 CONTRIBUTIONS
The project contributes:
- A hybrid speed/security architecture.
- Modular smart contract (ProductVerification.sol).
- End-to-end provenance demonstration.
- Role-based stakeholder dashboards.
- Accessible consumer verification tools.

1.7 WIND UP
This chapter has established the foundation for the project. The promise of decentralized blockchain technology motivates the design choices made to reduce the impact of counterfeit products.

CHAPTER 2: LITERATURE REVIEW
================================================================================

2.1 BACKGROUND ON COUNTERFEITING
Counterfeiting is a multi-billion dollar illicit industry. The consequences range from financial losses to life-threatening risks. The core challenge is establishing a trusted, tamper-proof verification mechanism.

2.2 TRADITIONAL ANTI-COUNTERFEITING METHODS
Methods like Holographic stickers, RFID, and NFC have evolved but remain vulnerable. RFID is expensive and centralized; NFC can be cloned; QR codes are easily copied. All rely on a central authority, which is a single point of failure.

2.3 BLOCKCHAIN TECHNOLOGY OVERVIEW
Blockchain provides a distributed ledger without a central authority. Ethereum extends this with Smart Contracts, allowing for programmable business logic. Immutability, transparency, and auditability make it ideal for supply chains.

2.4 COMPARATIVE ANALYSIS
(Comparison Table Summary)
- Centralized DB: Low Transparency, No Tamper-proof, Restricted Access.
- RFID: Medium Transparency, Hardware Required, High Cost.
- Blockchain (Proposed): High Transparency, Tamper-proof, Easy Mobile Access, Low Transaction Cost.

2.5 RESEARCH GAPS
Most existing solutions are enterprise-heavy and lack consumer-facing tools. This project addresses the gap by providing a full-stack, accessible, decentralized solution.

--- FILE: smart_contracts/contracts/ProductVerification.sol ---
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract ProductVerification {
    struct Product {
        string productID;
        string name;
        string manufacturer;
        string batch;
        string manufactureDate;
        address currentOwner;
        string status;
        bool isRegistered;
    }

    struct History {
        address previousOwner;
        address newOwner;
        string status;
        uint256 timestamp;
    }

    mapping(string => Product) public products;
    mapping(string => History[]) public productHistory;

    event ProductRegistered(string indexed productID, string name, address manufacturer, uint256 timestamp);
    event ProductTransferred(string indexed productID, address from, address to, uint256 timestamp);
    event ProductSold(string indexed productID, address retailer, uint256 timestamp);

    function registerProduct(
        string memory _productID,
        string memory _name,
        string memory _manufacturer,
        string memory _batch,
        string memory _manufactureDate
    ) public {
        require(!products[_productID].isRegistered, "Product already registered");
        products[_productID] = Product({
            productID: _productID,
            name: _name,
            manufacturer: _manufacturer,
            batch: _batch,
            manufactureDate: _manufactureDate,
            currentOwner: msg.sender,
            status: "Active",
            isRegistered: true
        });
        productHistory[_productID].push(History({
            previousOwner: address(0),
            newOwner: msg.sender,
            status: "Active - Registered",
            timestamp: block.timestamp
        }));
        emit ProductRegistered(_productID, _name, msg.sender, block.timestamp);
    }
    // ... (rest of the contract functions)
}
